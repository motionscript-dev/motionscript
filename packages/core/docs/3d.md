# 3D: the descriptor side

Core describes a 3D scene as plain data and never renders it. The vocabulary is `Graphics3D`, `Scene3D` and `RenderContext3D` with the geometry, material, light, camera and texture descriptors (`packages/core/src/render3d/`), the `Node3D` tree and `Canvas3D` that record it (`components/trees/three/node3d.ts`, the components in `components/builtins/three/three.ts` and `canvas3d.ts`, the `View3D` and `Material` modules), and `Fills.canvas3D`, which paints a recorded scene through any 2D shape (`attributes/shape/fill/implementations/canvas3d.ts`). A backend replays the recorded scene: the WebGPU renderer `@motionscript/renderer` draws it ([`packages/renderer/docs-3d-renderer.md`](../../renderer/docs-3d-renderer.md)), and why a renderer stays out of core is [why](./why.md#core-describes-3d-as-data-it-never-imports-a-3d-library). Nothing in `render3d/` imports a renderer: a backend registers its runtime and resource loader (`registerCanvas3DWarmup`, `registerCanvas3DResourceLoader`), and with none registered core is inert and usable headless.

## Model

3D follows the 2D split ([scene-graph.md](scene-graph.md)):

| 2D | 3D | What it is |
|---|---|---|
| `Graphics2D` | `Graphics3D` | what **one node** draws: shapes and paint / geometry and material |
| `RenderContext2D` | `RenderContext3D` | what a node draws into; siblings that share no members (a 3D component's `render` gets a narrower context over it, the sdk's `SceneContext`) |
| none | `Scene3D` | the recorded result a backend replays (it is also a `RenderContext3D`) |
| `Node2D` | `Node3D` | a thing in the tree |

`Graphics3D` holds drawables only (`mesh`, `instances`, `points`, `line`, `sprite`, `model` ops) and no hierarchy, light, camera or setting; those belong to the scene and the node tree. A `Scene3D` is the op list plus `push`/`pop` (one pair per node, keyed by node id), `light` and `camera` ops, and scene-wide fields: fog, environment, shadows, tone, post. It is rebuilt every frame; descriptors may be hoisted and shared.

```ts
Canvas3D({ width: "fill", height: "fill", fill: "#0b0d12", shadows: true, children: [
    Camera3D({ target: [0, 1, 0], orbit: 30, elevation: 18, distance: 6, fov: 45 }),
    DirectionalLight3D({ intensity: 2.4, position: [4, 6, 3], shadow: true }),
    Group3D({ id: "rig", children: [Box3D({ width: 2, cornerRadius: 0.15, fill: "tomato" })] }),
    Text({ text: "FPS 60", fontSize: 32 }),     // a 2D HUD over the 3D
] });

const scene = new Scene3D().perspective({ orbit: 20, elevation: 10, distance: 2.6 })
    .light({ type: "ambient", intensity: 0.4 }).draw(new Graphics3D().box({ width: 2, fill: "tomato" }));
Ellipse({ fill: scene });      // a bare Scene3D coerces to a canvas3D fill (resolveFill)
```

### Vocabulary

| Rule | Detail |
|---|---|
| `fill` is what a surface is made of | the whole 2D fill chain: a colour, gradient, image, video, a `Node2D` subtree, a built `Graphics2D`, a stack. `resolveFill3D` gives a colour (`color`), a texture (`map`), or rasterizes anything richer into a surface texture |
| Subdivision is `segments` | a number or a per-axis tuple the shape documents; partial revolution is `startAngle` + `sweep` |
| Axes are the real props | `x`/`y`/`z`, `rotationX/Y/Z`, `scaleX/Y/Z`; `position`/`rotation`/`scale` distribute into them (`distributeVectors`), so `to({ y: 3 })` needs no other axis; an axis stated beside the vector wins |
| Angles are degrees | Euler rotations, cone angles, sweeps, UV rotation; the backend converts |
| Optional means absent | an unstated field stays out of the descriptor so the backend's default applies |
| No `key` | reconciler identity is the node id plus a structural signature |
| The background is the viewport's 2D `fill` | there is no `Background3D` node; a sky that reprojects as the camera turns is `Environment3D` with `background`, and a `Fog3D` with no colour takes the viewport's |

Descriptor families, each a value discriminated on `type` with a `params` passthrough: `Geometry3D` (19 types, from `box` to `buffer`, `parametric`, `edges`, `wireframe`, `modelGeometry`), `Material3D` (15, from `basic` to `shader`), `LightData3D` (`ambient`, `hemisphere`, `directional`, `point`, `spot`, `area`), `CameraData3D` (`perspective`, `orthographic`). `Geo`, `Mat` and `Tex` stamp the discriminant. Four escape hatches in preference order: the full parameter surface of each descriptor, `Geo.buffer`/`Geo.parametric` vertex data, raw GLSL via `Mat.shader`, and the `params` passthrough, assigned onto the three object for materials, lights and cameras (not geometries or environments).

### Nodes

`Node3D` (`components/trees/three/node3d.ts`) adds only placement: `x/y/z`, rotation (with `rotationOrder`), `quaternion` (wins over rotation), `scaleX/Y/Z`, `lookAt` (a world point; wins over both rotations; snaps in a tween), `visible`, `shadow` (`true` casts and receives; `"cast"`, `"receive"`, `false`, or `{ softness, extent }`), `renderOrder`. `render(ctx)` opens one `begin`/`end` scope keyed by the node's id, calls `renderSelf`, then renders its `Node3D` children; every `renderSelf` reads props at the current frame and keeps nothing between frames. A `component3d` (`components/factory/component3d.ts`) is a generated `Node3D` subclass whose `renderSelf` runs the spec's `render` with a context over the scene being built: `time`, `draw(g3)`, `light`, `camera`, `fog`, `environment`. Built-ins, all components: `Group3D`, `Mesh3D` plus 14 geometry nodes, `Instances3D`, `Points3D`, `Line3D`, `Sprite3D`, `Model3D`, six lights, `Camera3D`, `Fog3D`, `Environment3D`; keys are in [registry.md](registry.md). A mesh component spreads `Material.state` (the `fill` shorthand and the material entries) and draws `Material.mesh(state, geometry)`.

**Commands.** Every `Node3D` has `moveTo` (`x`, `y`, `z`), `rotateTo` (`rotationX`, `rotationY`, `rotationZ`) and `scaleTo` (`scale` for every axis, `scaleX`/`scaleY`/`scaleZ` for one), each moving only what it is given. A scene is framed with `orbitTo`: on a `Canvas3D` it tweens the default camera's `orbit`, `elevation` and `zoom`; on a `Camera3D` its own `orbit`, `elevation` and `distance`, starting an unset field from what it reads as (`ORBIT_CAMERA_DEFAULTS`). `Camera3D.lookTo` tweens `target`.

**A parent's own coordinates.** `Node3D._spaceOf(child)` returns a `ChildSpace3D` (`toLocal(x, y, z)`) when the node places its children in coordinates of its own, the units of a graph say; `transform3D()` reads it for the child's position and nothing else, so a child keeps its size, turn and scale. A spec's `space` field (`component2d` or `component3d`) is that answer, so a viewport that is a graph gives its own 3D children its units; `parentSpaceOf(node)` asks whichever parent holds the node, and `projectNode3D` reads it too. It is the 3D counterpart of `Node2D._planeOf` ([dynamic-nodes.md](dynamic-nodes.md)).

`Canvas3D` (`components/builtins/three/canvas3d.ts`) is a `component2d` built like a `Rect` (`Paint`, `Flow`, `Shapes.corners`) with `View3D`, and `allowedChildren: ["2d", "3d"]`. Its 3D children go through a `Scene3D` each frame and its 2D children draw over the result as a HUD. `View3D.draw(ctx, state, extend?)` builds the scene (`ctx.scene3D()`, then the settings, the grid, and the default camera and lights where the scene has none, then `extend`) and paints `[...author fill layers, Fills.canvas3D(scene)]` as the box's fill through `Paint.draw`, so the scene sits above its own fill and below its children, overlay and stroke. A reusable viewport is a component of its own that does the same and passes `extend`, and hands the same `extend` to `View3D.load(loader, extend)` so what it draws is declared (recorded into a throwaway scene, declared as a `canvas3D` fill) and loads before a frame. Picking projects through the scene of any component whose `render` calls `ctx.scene3D()` (`_isViewport3D`, `_scene3D`), with no `instanceof Canvas3D`. Its props:

| Props | Notes |
|---|---|
| `maxPixelRatio` (2), `antialias` (true) | buffer ceiling; antialias is fixed at context creation |
| `shadows`, `tone`, `exposure`, `post` | render settings, props rather than nodes (a node with no position whose duplicate silently did nothing). `post` is recorded and not applied |
| `orbit` (35), `elevation` (20), `zoom` (12), `fov` (45) | default camera, used only when the tree has no camera. The camera takes `cameraOrbit(orbit)` = `90 - orbit`: this stored `orbit` is measured from +X, a camera's own from +Z (0 is head-on) |
| `ambientIntensity`, `keyIntensity`, colours | default light rig (ambient, a key, a weaker rim), used only when the scene records no light |
| `showGrid`, `showAxes`, `grid*` | an authoring ground grid, off by default; its horizon fades into the first solid layer of the viewport's `fill` |

### Resources

Each `Node3D` declares what it draws: the default `declareAssets` records `renderSelf` (never `render`) into a throwaway `Scene3D` and passes it to `declare3DResources`, so what loads is what draws and moving a node re-declares nothing. Cameras, lights and fog declare nothing (recording them would make an orbit or intensity tween a dependency); `Environment3D` declares from `src`/`faces`, not its rotation; `Canvas3D` declares the `three:runtime` loader (`View3D.load`). A 3D component's `declareAssets` is the same recording, of its `render`, with the context's `declaring` set: a component whose geometry is costly to build from data (math's surface and curve plots) draws its paint on a stand-in then, which also keeps an equation tween from re-declaring it every frame, since the declaration never read the equation. `declare3DResources` declares textures as images, glTF models and HDR/EXR panoramas as loaders keyed `three:<kind>:<src>` (`canvas3DResourceKey`; `src` is last and unescaped, so `parseCanvas3DResourceKey` splits on the first two colons), and each `Tex.surface` node source as a subtree of the declaring node (`assets.subtree`). The window rules are in [assets.md](assets.md).

## Depth: thin and touching geometry

Two faces at nearly one depth z-fight: the depth test picks a different winner from pixel to pixel and frame to frame, and the surface flickers in zig-zag stripes, worst where thin parts sit close together. Unless a camera sets both `near` and `far`, the renderer derives them from the scene bounds every frame (`reach = max(span, distance, 1)`, `near = max(0.01, reach/1000)`, `far = reach·10`, a perspective camera's derived `far` at infinity; [renderer](../../renderer/docs-3d-renderer.md), Frame step 2). Depth is reversed-Z float, so a gap of about distance ÷ 20 000 resolves in practice; the gaps below keep a wide margin, and renderers before reversed Z (0.1.1-alpha.0 and earlier) need it.

1. **Faces that overlap in one plane always fight**, at any precision: two solids never share visible face area. Inset, shrink or merge one. Flush side faces of touching parts (a beam flush with a slab's edge) count; a face hidden inside the other solid (the bottom of a box resting on a slab) does not.
2. **Anything laid on a surface sits a real gap above it**: lines, decals, strips, printing, grid bars. The gap is at least the camera distance ÷ 2000: 0.01 at distance 20, 0.0015 at distance 3. Hair lifts of 0.001–0.003 fight from across a board. A bar centred on a solid's edge is fine, because the half inside is hidden.
3. **Leave a camera's `near` and `far` unset.** A tiny `near` spends the depth range in front of the lens.
4. **`renderOrder` and translucency do not fix it.** `renderOrder` orders only within the opaque list or within the transparent list, and every transparent draw comes after every opaque one (Frame step 4). A translucent overlay still depth-tests against the face under it. `depthTest: false` is only for a layer meant to draw on top, such as hidden lines.
5. **An exactly coplanar decal** takes `polygonOffset` on the base material: `polygonOffset: true, polygonOffsetFactor: 1, polygonOffsetUnits: 1` pushes the base back. It applies from 0.1.1-alpha.1; earlier renderers ignore it, so a scene that must render on them keeps rule 2's gap.

## Invariants and traps

- **`g` is a `Graphics2D`; `g3` is a `Graphics3D`.** The two recorders take different ops and one scene routinely holds both (a `Graphics3D` for the 3D, a `Graphics2D` per `Tex.surface` source), so a bare `g` always means the 2D one.
- **The trees do not mix.** A `Node3D` is accepted only by a `Node3D` or a `Canvas3D`; anywhere else `add` throws.
- **A camera places itself, not its group.** three aims a camera's -Z at `lookAt` but a plain group's +Z, so a node whose `render` calls `ctx.camera` (`Camera3D`) has `groupTransform()` `{}` and its placement goes on the camera descriptor, still parent-relative (a camera in a moving rig is carried by it); its children stay in its parent's space. More than one camera keeps the last; a hidden camera records none, so the default camera applies. A camera is polar when `orbit`, `elevation` or `distance` is set (`isOrbitCamera3D`; `target` alone is not), and polar fields win over `position` and `lookAt`; elevation clamps to +-89.9 degrees.
- **Fog and environment are singletons**: no position, last writer wins (`fog(null)` and `environment(null)` clear). A fog with no colour takes the viewport's first solid fill, so the haze cannot drift from the backdrop.
- **`quaternion` is emitted only when it is not the identity**, because it wins over `rotation`; always sending it would make `rotation` silently do nothing.
- **A node's `shadow` reaches its meshes through scope**: a drawable that states no `shadow` takes the innermost open node scope's, and an op's own wins. Lights are the other way: `DirectionalLight3D`, `PointLight3D` and `SpotLight3D` default `shadow` to `false` in their `defaults` (N shadow maps, six faces for a point light), so `describe` reports it.
- **An attribute entry that must start unset is a `Types.custom`.** `Types.color()` (any attribute builder) called with `undefined` keeps its own default, so a light with that colour folded in renders the scene black; the built-in lights' colours are `Types.custom<Color | undefined>(undefined, { resolve, lerp })` (`modules/three-entries.ts`, internal).
- **A prop holding a non-number needs a `tween`** (`Types.custom(v, { lerp: lerpVector3 })`, `lerpEuler3`, `slerpQuaternion`), or `to()` leaves it alone. The built-in vector entries carry one: `Camera3D.target` tweens from the origin when unset, a node's `lookAt` between two set points (from unset it snaps).
- **A binding may read a clock**, because a bound prop recomputes on every read ([why](./why.md#a-bound-prop-recomputes-on-every-read-there-is-no-dependency-graph)), and a `render` reads `ctx.time`. Prefer a tweened prop: it is a row on the timeline.
- **What is cheap to animate**: transforms, material and light values and shader uniforms are in-place writes (`MUTABLE_MATERIAL_KEYS`). Geometry parameters are not (three geometries are immutable), so `Box3D({ width: () => span() })` reallocates every frame; animate `scaleX` instead. `STRUCTURAL_MATERIAL_KEYS` recompile the program: set once.
- **`Scene3D.isEmpty()` counts a light as drawable**, so a one-light scene is not empty. `View3D.scene` returns `null` (no default rig, no 3D pass) when there is nothing to show (no 3D child, no grid) and no `extend`. `assertBalanced()` throws on an unclosed `begin`; a node tree cannot unbalance itself, a hand-built scene can.
- **Accepted, recorded and not applied, with a one-time development warning** (`render3d/inert.ts`): the `post` chain, an environment's `src` and `faces` (only `preset: "studio"` renders), `params` on a geometry or an environment, `extends` on a shader material, and OBJ models (only glTF/GLB load).
- **Surface sources are values, not children.** `Tex.surface(source, { width, height })` takes a built `Graphics2D` or a `Node2D` subtree (default 512 square, `maxPixelRatio` 1); a source handed straight to `fill` gets those defaults. `resolveSurfaceSource` narrows structurally (`ops()` means `Graphics2D`) so `render3d` needs no value import of `Node2D`. A node source is bound by `View3D.draw` through `Node.attachDetached` (catalog, context, clock) and laid out on demand against `width` x `height`. **Hoist the source**: a fresh subtree per frame re-binds, re-lays-out and leaks, because texture identity is the source object. A fill chain bound to a mesh has no such identity, so `resolveFill3D` derives one from its values and marks the surface `static`.
- **`resolveFill3D` reads a bare string as a path when it looks like one** (`looksLikeAssetPath`: a leading `/` or `.`, or a known image, video or HDR extension), else as a colour. `lerpFill3D` interpolates two plain colours and otherwise holds the start until `t >= 1`.
- **Colours are core's `Color`** (`oklch()`, theme tokens, `"white/10"`); `parseColor` returns gamma-encoded sRGB ([attributes.md](attributes.md)).
- **A document row's `parentId` for a `Node3D` must be a `canvas3d` or another 3D node**; an unknown prop on a row is dropped without a report (`color` on a `Box3D` is ignored and the mesh stays white).
