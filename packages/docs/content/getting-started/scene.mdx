# Your First Scene

Welcome! In this guide you'll build a small animation from scratch, one page at a time. By the end you'll have a title card that slides in, gets laid out neatly, picks up a blur, and finishes with a mask reveal. Each page adds onto the example from the page before, so follow along in order.

Let's start with the absolute basics: a scene, a single shape, and getting it on screen.

## A scene is a document

In MotionScript a scene is **data**, not code. You describe it as a plain object: which nodes exist, what props they carry, and what happens to them over time. The engine works out what any frame looks like from that. Because a scene is plain JSON, it can be saved to a file, stored in a database, generated by a tool or sent to a server, and it renders the same everywhere.

There are two kinds of visual document:

- A **still** is a tree of nodes and nothing else. One frame, no timeline.
- A **composition** is a tree of nodes placed in time, plus a list of **commands**, each placed at a time. A node's row can say when it enters and leaves, which is how a composition says *when* each thing appears.

We'll write a composition, since the next page animates it. Give it a file of its own:

```ts title="src/scenes/my-scene.ts"
export default {
  kind: 'composition',
  nodes: [
    // your nodes go here
  ],
  commands: [
    // your animation goes here
  ],
};
```

The object is plain data, so a `.json` file works just as well.

## Add your first node

A scene starts empty. To put something on screen, add a **node**: a row in the document's `nodes`. Let's add a blue rounded square using the `rect` node.

```ts title="src/scenes/my-scene.ts"
export default {
  kind: 'composition',
  nodes: [
    { id: 'box', type: 'rect', parentId: null, layerOrder: 0,
      props: { width: 200, height: 200, fill: 'royalblue', cornerRadius: 16 } },
  ],
  commands: [],
};
```

That's it. You've placed a 200×200 blue square in the center of your scene. `commands` stays empty until the next page. Every node row has the same shape:

- `id`: how commands refer to it. We'll animate `box` on the next page.
- `type`: which kind of node it is: `rect`, `ellipse`, `text`, `video`, …
- `parentId` / `layerOrder`: where it sits in the tree. `null` puts it directly in the scene, and `layerOrder` orders it among its siblings.
- `props`: how it looks. List only what differs from the defaults.
- `startAt` / `endAt`: when it enters and leaves the scene, in seconds from the start. Leave them off, as here, and the node is there for the whole scene.

And the props we set:

- `width` / `height`: the size in pixels
- `fill`: the color (any CSS color name or hex value works)
- `cornerRadius`: how rounded the corners are

`rect` is the node you'll reach for most, but there are plenty of others. You can browse them all later under [Available Components](/docs/components/basic/text). For now, one square is all we need.

## Play it

A document doesn't play itself. An **engine** does: it holds the renderer, knows which node types exist, and opens documents. Create one engine for your app and open as many documents on it as you like.

In a browser:

```ts title="src/main.ts"
import { createBrowserEngine } from '@motionscript/browser';
import myScene from './scenes/my-scene';

const engine = await createBrowserEngine();

const canvas = document.querySelector('canvas')!;
const session = engine.open({
  document: myScene,
  viewport: { width: 1920, height: 1080 },
  fps: 60,
  target: canvas,
});

session.playback?.play();
```

`engine.open` returns a **session**: one document bound to one canvas. `viewport` and `fps` describe the output rather than the scene, so you pass them here instead of writing them into the document.

:::info Drawing with WebGPU
The engine draws with WebGPU, through the renderer `@motionscript/browser` builds in. A browser without it cannot draw: `createBrowserEngine` rejects with `WebGpuUnavailableError`, so check `isWgpuSupported()` first if you want to say so up front.

What the renderer could not draw (a shader that does not compile, say) is reported rather than thrown: each is an entry in `session.controller.buildErrors`, on its node. Exports and stills report the same through an `onIssue` callback, and if the GPU device is lost mid-export the export fails with a `RenderBackendError` whose `retryable` is `true` (the renderer has already moved to a new device), so you can simply run it again.
:::

In a React app, `useMotionPlayer` opens the session for you and `MotionStage` draws it:

```tsx title="src/Preview.tsx"
import { useMotionPlayer, MotionStage, type Engine } from '@motionscript/react';
import myScene from './scenes/my-scene';

export function Preview({ engine }: { engine: Engine | null }) {
  const player = useMotionPlayer({
    engine,
    document: myScene,
    viewport: { width: 1920, height: 1080 },
    fps: 60,
  });
  return <MotionStage player={player} />;
}
```

When you hand the player a different document, it swaps it into the running session rather than tearing the canvas down, so editing a scene keeps your place on the timeline.

Run it and you'll see your blue square sitting in the middle of the frame:

## More than one scene: the project

A lone document is a one-scene video. To lay several clips out on one timeline, say an intro and then a demo with music under both, write a **project** document. It is a list of tracks, and each track places one clip at a time:

```ts title="src/scenes/reel.ts"
import intro from './intro';
import demo from './demo';

export default {
  kind: 'project',
  name: 'My First Animation',
  fps: 60,
  viewport: { width: 1920, height: 1080 },
  tracks: [
    { id: 'intro', clip: intro, startAt: 0, duration: 3 },
    { id: 'demo', clip: demo, startAt: 3, duration: 6 },
  ],
};
```

- Each track places a `clip` (a still, a composition, or an audio document) at `startAt`, for a `duration` it must state. So a project's length is known from the document alone: it ends where its furthest track does.
- **Array order is paint order.** The first track is at the back, so a background is the first track and an overlay is the last.
- A project carries its own `viewport` and `fps`, so a host opens it with just `document`.

A project opens exactly like a single scene: `engine.open({ document: reel })`, or `useMotionPlayer({ engine, document: reel })`. In fact a single scene *is* opened as a project with one track.

## The project entry: custom node types

A document names its node types by key and nothing more. The types themselves are code, components written in TypeScript, and an engine only knows the ones it has been given. A project keeps its own in one entry file, `src/project.ts` by default, exported as plain values:

```ts title="src/project.ts"
import { PulseRing } from './components/pulse-ring';
import prism from './shaders/prism.json';

// Node types your documents may name, by `type`.
export const nodes = [PulseRing];

// Shader packs your documents may name.
export const shaders = { prism };
```

Hand the same values to the engine:

```ts
import { nodes, shaders } from './project';

const engine = await createBrowserEngine({ nodes, shaders });
```

Now any document opened on that engine can add a `pulseRing` node. The built-in nodes are always available, so you don't need this file until you write a node type of your own; see [Custom nodes](/docs/custom-node/introduction). Anything a JSON value can't express, such as a live function or a computed lookup table, belongs in a component.

:::info Rendering from Node
`@motionscript/headless` renders the same documents from a script or a server. It bundles your project entry, so your node types come with it, and takes the document per request:

```ts
import { createServerEngine } from '@motionscript/headless';

const server = createServerEngine({ projectRoot: '.' });
const { bytes } = await server.renderImage({ document: myScene, frame: 'last' });
```
:::

## Saving documents

A document you store should say which format it was written in. Give it `formatVersion: DOCUMENT_FORMAT_VERSION` when you save it; one without the field is read as the engine's own format. When an engine opens a document it brings one from an older 1.x format up to date first, so a scene saved by an earlier 1.x release still opens. Documents written by a 0.x engine are not supported. You can do the same yourself, to rewrite what you have stored:

```ts
import { DOCUMENT_FORMAT_VERSION, DocumentTooNewError, migrateDocument } from '@motionscript/sdk/v1';

const { document, from, to, changes } = migrateDocument(stored);
```

A document newer than the engine throws `DocumentTooNewError` instead of being read as whatever it happens to resemble.

A node whose type the engine does not know (a component you have not registered yet, or have removed) does not break the scene. It builds as an empty placeholder that keeps its id, its props and its children, draws nothing itself, and is reported in the player's `buildErrors`; commands aimed at it, and commands no node type publishes, are skipped and reported the same way. `validateDocument(doc, { registry: engine.registry })` reports both before anything is built, and `new Registry({ strict: true })` (`strict: true` on an engine) fails the build instead.
